# CDC 階層図・CDC 詳細図(非同期箇所の図)

**目的: 非同期対策を忘れている所を見つける。** RTL のどの階層に、どのクロックからどのクロックへの乗り換えがあり、
対策(同期化)があるか・ないか・誤っているかを、階層とクロックドメインの上に描く。

この図は RTL から作ったデータベースだけを元に、スクリプトが決まった手順で描く。
描く人(AI のモデル)の記憶や好みに頼る所はない。**下の「作業手順」をそのまま上から実行すれば、同じ RTL から同じ図が出る。**

| 図 | 見せるもの | 作り方 |
|---|---|---|
| **CDC 階層表** `cdc_matrix.svg` | 送り側の階層(行)× 受け側の階層(列)。乗り換えのあるマスに印・件数・ドメインの組。**線を描かない**(検出用の主役) | `cdcdiag.py hier`(`rtldb.py analyze` でも出る) |
| CDC 階層図 `cdc_hier.svg` | 階層(行)× クロックドメイン(列)の上に、乗り換えを線で(つながりを見せる説明用) | 同上 |
| CDC 詳細図 | 乗り換え 1 本の回路(送り側の FF・途中の論理・同期化の段・取り込み) | `cdcdiag.py detail` → `gatediag.py render` |
| ドメインの表 `cdc_map.svg` | ドメイン × ドメインの件数(全体の量) | `rtldb.py analyze` |
| 一覧 `cdc.md` | 全件・準静的の候補・階層の深さ・リセット(RDC) | `rtldb.py analyze` |

## 作業手順(AI 向け。モデルが変わってもこのとおりに行う)

守ること:
- 図の SVG を手で書かない・直さない。見た目を変えたい時は `scripts/cdcdiag.py` と下の「決まり」を直し、`rules/style_rules.yaml` の R54 に残す。
- 分類を頭で判断しない。判断は `rtldb.py` が行う。結果がおかしいと思ったら、手順 6 で経路を出してソースと突き合わせる。
- 推測で宣言(`--static` / `--async-in` / `--gray`)を足さない。足す時は理由を利用者に確認し、決定事項に残す。

### 0. 準備
```
pip install pyslang pyyaml          # slang(SystemVerilog のエラボレータ)
python3 scripts/rtldb.py selftest   # 2 行とも OK になること。NG なら先に直す(図を描かない)
```

### 1. 入力を確かめる(足りなければ聞く)
| 要るもの | 無い時 |
|---|---|
| RTL のファイル一覧(`-f files.f` か並べる)・最上位モジュール名・インクルードのパス・マクロ | 利用者に聞く |
| 外から来る非同期の入力端子(ボタン・割り込み・別チップの信号) | 聞く。未決なら宣言なしで進め、「入力端子は未宣言」と報告に書く |
| 動作中に変えない設定レジスタ・OTP の値 | 手順 4 の候補の表を見せて聞く |

### 2. データベースを作る
```
python3 scripts/rtldb.py build -f files.f --top TOP -I inc -D SYNTHESIS -o out/design.db
```
出力の確認:
- 「slang のエラー n 件」: 0 でなければ内容を報告に書く(未定義のモジュールはブラックボックスになる。PLL などは問題ない)。
- インスタンス数・FF 数が想定と桁で合っているか。

### 3. 解析して図を出す
```
python3 scripts/rtldb.py analyze out/design.db -o out/ --png [--async-in '正規表現'] [--static '正規表現'] [--gray '正規表現']
```
`out/cdc.md`・`cdc_map.svg` と、図が両方の形で出る: `cdc_matrix.svg`(表・対策なしと誤りだけ)、`cdc_matrix_all.svg`(表・全部の重さ)、
`cdc_hier.svg`(線・対策なしと誤りだけ)。対策なし・誤りが 0 件の時は、全部の重さで描く。まず `cdc.md` の「クロックドメイン」を見る。
- ドメインが 1 つしかない、または想定より少ない → クロックが 1 つに混ざっている疑い。`reference/rtldb.md` の「限界」を見て、原因を報告する。
- ドメインの種類が `undriven` → クロックの源が RTL の中にない(アナログのモデルなど)。そのまま別ドメインとして扱ってよい。

### 4. 対策忘れを確かめる(この図の主目的)
`cdc.md` の「対策なし」「対策の誤り」を上から見る。
1. 「準静的な設定レジスタの候補」に出ている送り側は、利用者に「動作中に変えないか」を聞く。変えないなら `--static` で宣言して手順 3 をやり直す。
2. 残った「対策なし」は、対策忘れの疑いとしてそのまま報告する(勝手に除外しない)。
3. 「対策の誤り: グレイコードでない多ビット」は、送り側の代入の記述を確かめる。グレイコードなのに読み取れていない書き方なら
   `--gray` で宣言(理由を残す)、そうでなければ対策の誤りとして報告する。

### 5. 図を仕上げる(表と線の両方を出す)
```
python3 scripts/cdcdiag.py hier out/design.db -o out/ --png --sev bad                              # cdc_hier(線)と cdc_matrix(表)。対策なし・誤りだけ
python3 scripts/cdcdiag.py hier out/design.db -o out/ --png --name cdc_hier_all                    # 全部の重さ
python3 scripts/cdcdiag.py hier out/design.db -o out/ --png --sev bad --focus u_xxx --name cdc_hier_xxx   # 1 ブロックに絞る
```
- `--style` の既定は `both`(線の `名前.svg` と、表の `名前の hier を matrix に替えたもの.svg` を出す)。片方だけなら `--style lines` / `--style matrix`。
- **対策忘れを見つける時は、まず表(cdc_matrix)の赤いマスを見る。** 線の図は、つながりを人に説明する時に使う(線が 15 本を超えたら表を使う)。
- `--sev` で重さを絞ると、その重さの乗り換えがある枝だけが行になる。
- 全体の図で「▸ 下位 n 段を含む」とたたまれた行に赤い印・線があれば、その行を `--focus` にした図を足す。
- 線の図で一覧の最後に「ほか n 組は線を省略」と出たら、`--focus` で分けるか、表を使う。
- 出した PNG を必ず自分で見て、下の「できあがりの確認」を通す。

### 6. 1 本ずつ確かめる・見せる
```
python3 scripts/rtldb.py path out/design.db --src '送り側の正規表現' --dst '受け側の正規表現'      # 階層をまたぐ信号の並び
python3 scripts/cdcdiag.py detail out/design.db --dst '受け側の正規表現' -o out/cdc_x.yaml
python3 scripts/gatediag.py render out/cdc_x.yaml -o out/ --png                                 # lint の [CDC] も見る
```
「対策なし」「対策の誤り」から最低 3 本(多い順)は `path` で経路を出し、ソースの該当行と合っているかを確かめてから報告する。

### 7. 報告に書くこと
- 規模(行数・インスタンス・FF・階層の深さ)と所要時間、slang のエラー数。
- ドメインの一覧、対策なし / 対策の誤り / 要確認 / 対策あり の件数(受け側の FF 単位)。
- 宣言したもの(`--static` / `--async-in` / `--gray`)と理由。未宣言で残した前提。
- ソースと突き合わせた本数と結果。限界(`reference/rtldb.md`)のうち今回当てはまるもの。

- [ ] 表(cdc_matrix)と線(cdc_hier)の両方が出ている。表の赤いマスが全部、下の内訳に #番号つきである。
- [ ] 線の図は、赤い線(対策なし・誤り)が全部、番号つきで一覧にある。省略があれば組数が書いてある。
- [ ] 線が重なって追えない所がない(追えなければ `--focus` で分ける)。

## 分類と線(4 段)
| 重さ | 線・番号の形 | 分類 | 意味 |
|---|---|---|---|
| **対策なし** | 赤系・太い実線、塗りの丸 | `no_sync` 同期化が見つからない / `data_enable` 取り込みの条件が同期化されていない / `mem` メモリのポインタの同期化がない | 対策忘れの疑い |
| **対策の誤り** | 赤系・一点鎖線、塗りの四角 | `sync_bus` グレイコードでない多ビットを FF で同期化 / `sync_logic` 同期化の前に論理 / `sync_tap` 1 段目の出力を使用 | 同期化はあるが効かない |
| 要確認 | 橙系・破線、白地に橙の丸 | `gated` 同期化した信号と論理で合わせる / `reconv` 再収束 / `clk_as_data` クロックをデータに | 形はあるが、人が確かめる |
| 対策あり | 緑系・細い実線、白地に緑の丸 | `sync` 2 段以上 / `sync_gray` グレイコード / `sync_pulse` エッジ検出 / `fifo` 非同期 FIFO / `handshake` | 構造として対策がある |

**グレイコードは名前で判断しない。** 代入の記述(`X ^ (X >> 1)` など。`reference/rtldb.md`)で確かめる。
グレイコードの記述があるだけでは何も指摘しない(非同期とは限らない)。乗り換えで多ビットを FF で同期化している所で、
送り側にグレイコードの記述がなければ「対策の誤り」になる。

## 行の作り方(表と線に共通。R54)
**行(階層)**
- 行にするのは、乗り換えの端(送り側・受け側の FF)があるインスタンスと、その祖先だけ。
- 並びは階層パスの順(親の下に子、字下げ 16px、行の高さ 30px)。行の名前は上の行からの相対パス(generate の名前も入る)。右端にモジュール名と深さ。
- 子が 1 つだけで自分に端のない中間の階層は、子と 1 行にまとめる(`u_tx …(5 階層)… u_n`)。
- 同じモジュールの葉の兄弟が 4 つ以上あれば 1 行にまとめる(`u_wkup_detector_* ×19`)。
- **つながり方が同じ行をまとめる**(同じ内容を何度も描かない): 乗り換えの相手の行・向き・重さがまったく同じ兄弟は 1 行(×n)にし、
  子が全部、親と同じつながり方なら親の行にたたむ。まとめた後でまた同じになる行が出るので、変わらなくなるまで繰り返す。
- 行が上限(`--rows`、既定 36)を超える時は、浅い階層から、同じ深さでは重い枝(対策なし・誤り → 要確認 → 件数)から行にし、入りきらない枝は親の行にたたむ(▸ 下位 n 段を含む)。
- `--focus` で絞った時、外にある端は一番下の「(この階層の外)」の行にまとめる。

## CDC 階層表の決まり(線を描かない形)
- 行 = 送り側の階層(上の「行の作り方」)。左から、行の番号・階層の名前・モジュールと深さ・その行にあるクロックドメインの札(記号と FF 数。乗り換えの端になるものは塗る)。
- 列 = 受け側の階層。受け側になる行だけを、行と同じ順で並べる。見出しは行の番号(黒丸)と行の名前。列が 12 までは幅 132px で名前を 2 行、
  13 以上は幅 62px で名前を斜め書きにし、マスは印と件数だけにする。
- マス = その行の階層から、その列の階層への乗り換え。重さごとに 1 行ずつ「印・件数(受け側の FF 単位)・ドメインの組(A→C,D)・#番号」。
  マスの地の色は一番重いもの(対策なし・誤り = 薄い赤に赤枠、要確認 = 薄い橙、対策あり = 薄い緑)。
- 印: 対策なし = 塗りの丸、対策の誤り = 塗りの四角、要確認 = 白抜きのひし形、対策あり = 細い輪(色だけに頼らない)。
- 列がその行自身に当たるマスには斜めの線を引く(同じ行の中の乗り換えはそのマスに書く)。
- 上にクロックドメインの凡例(記号・クロックの源・種類・FF 数)。下に印の凡例・読み方、その下に「対策なし・対策の誤り・要確認の内訳」
  (#番号・送り側 → 受け側・分類ごとの件数・例の信号。40 件まで)。
- 行の高さは 30px。1 つのマスに複数の重さがある行は、1 行あたり 18px 足す。

## CDC 階層図の決まり(線でつなぐ形)
**列(クロックドメイン)**
- 乗り換えに出てくるドメインだけ、FF の多い順に A, B, C…(10 列まで)。見出しに記号・クロックの源の名前・種類・FF 数。色だけに頼らず記号を併記する。
- マス = その行(と、下の行に出していない下位)にある、その列のドメインの FF 数。乗り換えの端になっているマスは太枠で塗る。FF のない端(入力端子・データに使ったクロック・外)は破線のマス。

**線(乗り換え)**
- 同じ(送り側の行・受け側の行・重さ)は 1 本にまとめる。ドメインの組は、端のマス(● と ▶)と一覧の記号で示す。
- 送り側のマスの右端に ●、右の通路に出て縦に進み、受け側のマスの右端に ▶ で入る。
- **線の重なりを減らす**: 送り側か受け側が同じ線は 1 本の幹線に束ねる。重さごとに、線の多い行から順に束ね(同数なら受け側を優先)、
  分岐・合流の点に丸を打つ。幹線は短いものから内側の通路に置く(幹線どうしの間隔 34px。`--lane` で変えられる)。
- 同じ行の中の乗り換えは、マスからマスへまっすぐ(右向きは上、左向きは下に 10px 刻みでずらし、本数が多い行は高さを増やす)。
- **線どうしの間を空ける**: 1 つの行に複数の線が出入りする時は、通路の内側の順に 14px 刻みで上下にずらし、**その行だけ高さを増やす**(高さ = max(30, 線の数 × 14 + 18)px)。ほかの行は 30px のまま。間隔は `--gap` で変えられる(詰めたい時は 8、もっと空けたい時は 18)。番号どうしは横に 26px ずつずらす。
- **線を追いやすくする**:
  - 線の両端に同じ番号を置く。置く場所は、マスの列のすぐ右の「番号の帯」(通路の左)。行の中では通路の内側の順に、左から右へ階段状に並べる。
    線をたどらなくても、同じ番号を探せば相手の行がわかる。束ねた幹線の根元には、束ねた線の番号をまとめて書く(`3–6`、`10,21,23–28`)。
  - 隣り合う線は色を変える。同じ重さの中で 3 色を用意し(対策なし・誤り = 赤 / えんじ / ピンク、要確認 = 橙 / 茶 / 黄土、対策あり = 緑 / 青緑 / 黄緑)、
    同じ行で隣り合う線・隣の通路の幹線がまだ使っていない色を選ぶ。番号の色も線と同じにする(一覧の番号も)。
    色の違いは見分けるためだけで意味はない。重さは線の種類(実線・一点鎖線・破線・細線)と番号の形(塗りの丸・塗りの四角・白地の丸)で示す。
    1 色に戻す時は `--mono`。
  - 線には白い縁(5.5px)をつけ、交わる所で上下が分かれて見えるようにする。つながる所(分岐・合流)にだけ丸を打つ。
  - SVG をブラウザで開いた時は、番号か一覧の行にマウスを乗せると、その線だけが残る(ほかは薄くなる)。資料に貼る PNG には影響しない。
- 線は重い順・件数の多い順に番号を振り、`--arcs`(既定 28)本まで描く。残りは一覧の最後に組数だけ書く。`--sev` で描く重さを絞れる。

**一覧(右)**: 番号ごとに 2 行。「[ドメインの記号…] 送り側の行 → [記号…] 受け側の行」と「重さ: 分類ごとの件数(受け側の FF 単位)・例の信号」。
見出しの件数は、受け側の FF 1 本を一番重い分類で 1 回だけ数える。

**凡例(下)**: 線の 4 種類、読み方、行のまとめ方、グレイコードは記述で確かめること、判定は構造だけを見たものであること。

## CDC 詳細図の決まり
ゲートレベル図(R52)の書式で、受け側の FF 1 本について次を置く。FF は段ごとに等間隔。
- 左の囲み(青)= 送り側ドメイン: 送り側の FF(4 本まで)。右の囲み(紫)= 受け側ドメイン。
- 対策あり(同期化): 送り側 → 同期化の段(実際の FF 名)→ 出力。エッジ検出は XOR を足す。
- ハンドシェイク・非同期 FIFO: データの FF(メモリ)と、条件を運ぶ FF → 同期化 2 段 → 取り込みの箱 1 つ → 受け側の FF。
- ゲートの形: データと同期化した信号を AND の記号で合わせてから受け側の FF。
- 対策の誤り(同期化の前に論理): 送り側の FF → 「組み合わせ論理」の箱 → 同期化の段。
- 対策なし: 送り側の FF(→ 論理)→ 受け側の FF。`gatediag.py` の lint が [CDC] を出す(判定の二重の確認になる)。
- **箱は横に広げない**: FF の段の間に置く箱は 1 つにまとめ、名前は全角 6 字で折り返して 2〜3 行にする(「空でなければ / 読み出す」)。
  くわしい説明は題の下の注記に書く。題は信号名の最後の 2 階層、長い階層パスは注記に書く。

## 未決の時に聞くこと
- 外から来る非同期の入力端子はどれか(`--async-in`)。
- 動作中に変えない設定レジスタ・OTP の値はどれか(`--static`)。理由も残す。
- 分周クロック・切替クロックを元と同期とみなしてよいか(既定: 分周は同期、切替は別ドメイン)。
- 記述から読み取れないグレイコード(ビットごとの generate など)があるか(`--gray`)。
