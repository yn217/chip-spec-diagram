# リセット系統図

リセット源 → リセット制御(OR・PLL ロック待ち・伸長)→ 同期化 → リセットドメイン、を左から右へ描く。
下に解除シーケンスの波形、右にリセットドメインをまたぐ接続(RDC)を描く。
バス構成図と同じ `diagram.yaml` を使うので、ブロック名・クロックは図どうしで一致する。

## 入力(`resets:`、書式は `reference/dsl.md`)
- `sources` … リセット源。`kind`: por / bod / pad(チップ外から端子経由)/ wdt / sw / dbg
- `domains` … リセットドメイン。`sources`(OR)・`clock_domain`(解除を同期させるクロック)・`sync`(段数)・
  `stretch`(伸長サイクル)・`wait`(待つ PLL)・`after`(先に解除するドメイン)・`isolation`(単独リセット時の切り離し)
- `default` … `reset_domain` を書いていないブロック・バスの所属
- ブロック・バスに `reset_domain:`。子ブロック・CPU に付けたキャッシュは親を継ぐ。

## 手順
1. G0 と同じく状況を確認。RTL があればリセット端子(`*rst*` `*reset*`)と同期化回路を読み、無ければ質問する
   (`templates/question_bank.yaml` の reset_sources / reset_domains / reset_sequence)。
2. 未決は仮置き(POR・RST_N・WDT、クロックドメイン単位、PLL ロック → system → その他、同期 2 段)にして決定事項ログに残す。
3. 生成: `python3 scripts/resettree.py diagram.yaml -o out/ --png` → `reset_tree.svg` と `reset.md`(源×ドメインの表・解除順・RDC 一覧)。
4. lint が OK になるまで直す。PNG を見て線と文字を確認する。ビューア(`viewer.py`)にも節が入る。

## チェック(lint)
| タグ | 内容 |
|---|---|
| [リセット未割当] | `reset_domain` も `default` もないブロック・バス |
| [未定義] | 存在しない源・ドメイン・PLL・クロックの参照 |
| [順序] | `after` の循環 |
| [同期] | 解除の同期化が 2 段未満 |
| [PLL] | ドメインのクロックが PLL 由来なのに、そのロックを(`after` をたどっても)待っていない |
| [RDC] | 片側だけが単独でリセットされうる接続。相手が動いたまま X/グリッチを受ける。どちらかのドメインに `isolation: true`(切り離し/静止化)があれば対策ありとして緑で表示 |

## 描き方の決まり(R48)
- リセット源ごとに 1 列。源の札を列の上に置き(外部端子はチップ枠の外に破線で、枠の上辺にパッド)、列ごとに縦線を引き、
  そこから右へ各ドメインの OR へ枝を伸ばす(分岐点に丸)。源ごとに色を変え、列・枝・波形を同じ色にする。
- 枝は白い縁取りの上に描き、交差する他の列は途切れて見えるようにする(つながっていない交差と分岐を見分ける)。
- 多くのドメインに入る源ほど左の列に置く(短い列が右に来て交差が減る)。
- 入力が 1 本なら OR は描かない。リセット制御は破線の枠でまとめ、PLL ロック待ち・伸長を OR の出力の上に書く。
- 同期化の箱はドメインのクロックの色で、段数とクロック名・周波数。出力線にリセット信号名(既定 `<domain>_n`)。
- ドメイン枠の色はクロックドメインの色を継ぐ(クロック系統図と揃える)。右上に解除の順番。
- 波形は負論理(L = リセット中)。POR・外部端子 → PLL ロック → ドメインの順に段を進め、伸長を「+Ncyc」で書く。
