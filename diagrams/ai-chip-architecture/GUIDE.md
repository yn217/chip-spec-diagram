# AI チップのアーキテクチャ図(積層あり)

SoC(CPU + バス + 周辺)ではなく、**演算タイルの並び + メモリ + 高速 I/O** でできた AI 向けチップの全体像を 1 枚に描く。
積層(ダイを重ねる)があり、「どの層を、どちらから見た図か」を取り違えないことが要る。

**考え方: モデルは 1 つ、図は同じ配置の使い回し。** 全体把握用の図を作ったら、動作説明も切り出しも層ごとの図も、
同じ配置・同じ線・同じラベルの位置のまま、見せ方(薄くする・切り出す・層を絞る)だけを変える。
図ごとに配置が変わると、読む人はどれが同じブロックかを探し直すことになる。
階層の 1 段下(ブロックの中の回路)だけは別図にし、その別図の中でまた同じ配置を使い回す。

| 図 | ファイル | 使う時 |
|---|---|---|
| 全体図 | `arch_overview.svg` | 全体把握。データの流れが主役。積層は 1 枚に重ねる(上の層 = 色つきの枠 + 斜線 + 「L2」の札) |
| 層ごとの図 | `arch_layer_<層>.svg` | 物理配置を見る時。全体図と同じ向き・同じ位置で、ほかの層は薄い枠だけ |
| 層ごとの図(設計データの向き) | `arch_layer_<層>_design.svg` | 全体図では裏から見えている層を、回路面から見た向きで。レイアウト担当と話す時 |
| 動作説明 | `arch_scene_<id>.svg` | 全体図と同じ配置で、登場しない所を薄くし、登場する線に番号。下に動作の表 |
| 動作説明のコマ割り | `arch_scene_<id>_frames.svg` | 同じ線を何度も使う動作。同じ図を 1 ステップずつ並べる(`frames: true`) |
| 切り出し | `arch_crop_<id>.svg` | 全体図の一部を拡大。どこを切り出したかの小さい地図つき |
| 別図(線の種類) | `arch_focus_<種類>.svg` | 全体図に描かない線(BIST の接続とセレクタ = test、クロック = clk)。全体図と同じ配置 |
| 別図(中の回路) | `arch_detail_<id>.svg` | ブロックの中の回路(データパス)。回路図ふうの記号で描く。動作説明・コマ割りも出る |
| 表 | `arch.md`・`arch_detail_<id>.md` | 積層と向き・クロック・ブロック・接続(幅 × クロック = 帯域)・動作の表 |

```
python3 scripts/aichip.py render examples/aichip/infer_accel.yaml -o out/ --png
python3 scripts/aichip.py lint   examples/aichip/infer_accel.yaml
```

## 作業手順(AI 向け。モデルが変わってもこのとおりに行う)
1. **聞く**(未決なら仮置きして進め、決定事項に残す。質問は `templates/question_bank.yaml` の `aichip_*`):
   積層の枚数と順・各層の回路面の向き(Face-up / Face-down)・裏返す軸、図の視点(上面 / 下面)、
   ブロックと位置、接続のビット幅とクロック・片方向か両方向か、クロックの源と周波数、説明したい動作、中の回路まで描くブロック。
2. **マス目を決める**: チップの縦横比に合わせて列 × 行(例 12 × 8)。1 マス = 一番小さいブロック。
   クロック・電源・温度・BIST の小さい箱は 1 行にまとめる(その行は自動で低くなる)。
3. **model.yaml を書く**(下の「書き方」)。座標はすべて「上面から見た向き」。
   線の種類を分ける: データ = `data`、設定・制御(I2C・SPI・CSR を含む)= `ctrl`、BIST・デバッグ = `test`、クロック = `clk`。
4. `aichip.py render` → **lint を 0 件にする**(下の表)。0 にできないものは理由を決定事項に書く。
5. **PNG を自分で見る**: 文字が読めるか、線がどこからどこへか追えるか、薄くした図で登場する所が目に入るか。
6. 動作説明は `scenes:`、一部の説明は `crops:` に足す。**別の配置の図を作らない。**
7. **中の回路を描くブロック**は `details:` に回路として書く(R60)。処理の手順を箱で並べない。
   先に信号の流れを紙に書く: どのメモリのどの端子から読み、どのレジスタで受け、どの演算器を通り、どのセレクタで選び、どこへ書き戻すか。
   それをそのまま 記号(shape)・端子(pins)・線(ブロック.端子)にする。データは左 → 右、制御は上の行、戻りの線は下を回る。
8. **動作が同じ線を何度も通る時**(読む → 演算 → 書き戻す → 読み直す → 演算器を切り替える)は、
   ステップごとに `state:`(セレクタの向き・メモリの読み書き・レジスタの動き)を書き、`frames: true` でコマ割りも出す(R61)。
9. 図の見た目を変えたい時は SVG を手で直さず、`scripts/aichip.py` とこの GUIDE、`rules/style_rules.yaml`(R55〜R61)を直す。

| lint | 意味 | 直し方 |
|---|---|---|
| `[空き]` マス | その層の範囲にブロックのないマスがある(回路の図では見ない) | 詰める。何かあるならブロックとして書く(容量・配線領域など) |
| `[空き]` ブロック | 3 マス以上のブロックの中が空いている | 小さくするか、`inside:` で中身を書く。回路まで描くなら `details:` |
| `[情報]` | 線に幅とクロックがない / ブロックにクロックがない(回路の図では幅だけ見る) | 書く。クロックで動かないブロックは `clock: none` |
| `[帯域]` | 書いた帯域と、幅 × クロックの計算が合わない | どちらかを直す。稼働率は `eff:` |
| `[接続]` | ブロック・端子がない / 層をまたぐのに `via` がない / 上下に重なっていない | 重なる位置に置く。引き回すなら `far: true`(印を両方に)か `far: line`(線で結ぶ) |
| `[重なり]` | 文字どうしが重なっている | 位置・`label_at`・`inside_at` を変える。詰めた方がよい所だけ `tight: true` |
| `[動作]` | 動作説明の線・`state` のブロックがない / 全体図に描かない種類の線を使っている | 名前を直す。BIST・クロックの動作は別図で説明する |
| `[配置]` `[経路]` `[切り出し]` | 位置の重複・はみ出し、通り道なし、名前の間違い | モデルを直す |

## 描き方の決まり

### R55 同じ図を使い回す
- 配置・配線・ラベルの位置は 1 回だけ決め、全体図・層ごとの図・動作説明・切り出し・別図(線の種類)で共有する。
- 動作説明: 登場しないブロック・線・文字を薄い灰色にし、登場するブロックの枠と線を橙にする。線の上に手順の番号。
  手順の文は図の下に並べる。番号は線の上で、文字に重ならない所に置く。
- 切り出し: 指定したブロックを囲む範囲を拡大(最大 2 倍)。上の帯に、全体図のどこかを示す小さい地図。
- 1 回の動作で線が多すぎる時は、動作を分ける(図を作り直すのではなく、`scenes:` を増やす)。

### R56 密に、情報を省かない
- **マス目に敷き詰める。** ブロックの間は配線用のすき間(32px)だけ。外周も同じ幅の通路 1 本。空きマスを作らない。
- **ブロックに書くもの**: 名前(10.5px 太字)・諸元(7.5px。個数・容量・方式)・クロック名と周波数(クロックごとの色の ■ つき)。
  3 マス以上のブロックは `inside:` で中身を書く。中身は処理の手順ではなく**回路の要素**(FIFO・SRAM・演算器・レジスタ・セレクタ)。
- **線に書くもの**(6.8px): 1 行目 `ビット幅×クロック`、2 行目 `向きと帯域・プロトコル`。直列は `レーン数L×速度`。帯域 = 幅 × クロック ÷ 8(GB/s はバイト)。
  - **線の太さ = ビット幅**(32b 以下 1px 〜 4096b 6px。直列はレーン数 × 32b 相当)。矢じりと ⊠ の大きさも太さに合わせる。
  - **向き**: `→128GB/s` = 片方向、`⇄各128GB/s` = 両方向でそれぞれこの帯域(`dir: both`。矢じりが両端)、`⇄交互125kB/s` = 半二重(`dir: half`。I2C など)。
  - 色: 紺 = データ、灰 = 制御、上の層の中のデータ = その層の色。
- 字は小さくてよい(拡大して読む前提)。**図が込み入ってもよいが、情報を別の表に逃がさない**(表 `arch.md` は控え)。
- 繰り返しのブロック(タイル ×8 など)も 1 つずつ描き、全部にラベルを書く(`array:` と `for:` で書く手間は減らす)。

### R57 文字の重なり
- **文字と文字は重ねない**(`[重なり]`)。
- 文字が枠・線の上に乗るのは許す(線の上のラベルには白い縁)。ただし線に沿って文字を重ねない。**線のラベルはブロックの上に置かない**(すき間に置く)。
- ラベルの向きは、置く場所のすき間で決める: **縦のすき間 = 縦書き(下から上)、横のすき間 = 横書き**。
- ラベルは線の一番長い区間から順に、中央 → 端寄り、上 → 下の候補を試し、重ならない最初の候補に置く。1 行に収まらなければ 2 行。
- すき間を広げれば避けられるが、広げると間延びする所は `tight: true` で重なりを許す。
  **許すのは、枠や並びから何が書いてあるか推測できる場合だけ**(繰り返しの 2 個目以降など)。理由を決定事項に残す。

### R58 積層と向き
- **座標は「上面(放熱側)から見た向き」で全層を書く。** 左上が [0, 0]。
- **全体把握 = 1 枚に重ねる。層は色で分ける(破線・点線の枠は使わない。どこまでが枠か分かりにくい)。**
  - 上の層のブロック = その層の色(2 層目は紫)の**実線の閉じた枠** + **斜線**(斜線の色 = 種類。**SRAM は橙**)+ 角に層の名前の札(「L2」)。
  - 上の層の範囲 = 同じ色の実線の外形 + 「L2 メモリダイ の範囲」の札。
  - 文字は 1 層目が左上、2 層目が右下(同じ位置のブロックの文字がぶつからない)。上の層は斜線だけで塗らない(下の層の色を消さない)。
- **SRAM の場所は橙**: メモリのブロック(`kind: mem`)、ブロックの中の SRAM(`inside` の `mem:`)、回路の図の SRAM(`shape: ram`)。
- **層をまたぐ接続 = ⊠。** 2 つのブロックが上下に重なっている位置に置き、横に `HB 幅×クロック` と `向きと帯域・用途` を書く。
  HB(ハイブリッドボンディング)・µバンプ・TSV は真上・真下でしかつながらないので、重なっていなければ `[接続]`。
- **物理配置を見る時 = 層ごとの図。** 全体図と同じ位置のまま、その層だけを色つきで、ほかの層は薄い枠だけ。層が小さければその範囲に切る。
- **どちらから見た図かを、どの図にも書く**(上の帯):
  - 視点(上面から透視 / 下面から透視)。
  - 層ごとに「回路面 上(Face-up)/ 下(Face-down)」と「表から見ている = 設計データと同じ向き」か
    「裏から透かして見ている = 設計データと左右(上下)が反転」。
  - 断面(横から見た積み方)。太い線の側が回路面。視点の矢印。層の間に接続の種類(HB・ピッチ)。
- **原点の印(▶)と F の字**を各層の設計データの原点の角に描く。裏から見ている層は F が鏡文字になる。
- 全体図で裏から見えている層には、**設計データの向きの図**(`_design`)も出す。全体図と左右が反転することを題に書く。
- 下面から見る図(`view: bottom`)は、上面から見た向きを左右に反転する。文字は反転しない。

### R59 全体図はデータの流れが主役。関係の薄いものは小さい箱、その接続は別図
- **名前だけの小さい箱**: PLL・クロック生成・電源管理・温度/電圧モニタ・LDO・BIST・JTAG(`small_kinds: [clk, pwr, test]`。個別には `small: true / false`)。
  小さい箱だけの行は低くなる(24px)。ふつうの行にある小さい箱は、マスの角に置く。
- **全体図に描く線 = `focus: [data, ctrl]`。** それ以外の種類(`test`・`clk`・`pwr`)の線は全体図に描かず、
  **同じ配置の別図** `arch_focus_<種類>` に描く(その種類の線とつながるブロックだけを橙、ほかは薄く)。
  - BIST: 箱だけを全体図に置き、BIST → 各メモリの接続と**セレクタ**(`mux: "通常/BIST"`。行き先の手前に台形)は `arch_focus_test`。
  - クロック: PLL → クロック生成 → 各ブロックの配り方は `arch_focus_clk`。
- **I2C・SPI・CSR は全体図に描く**(`kind: ctrl`)。遅くても、設定・起動コード・状態の読み出しはここを通る(データの移動に要る)。
- **FIFO は小さいアイコン**(長辺を接した長方形 4 つ。`inside` の `fifo:名前`)。箱にしない。

### R60 ブロックの中の回路は別図。論文の回路アーキテクチャ図のように記号で描く
- 全体図のブロックに「▸中の回路: 別図 <id>」と書き、中は `details:` → `arch_detail_<id>` に描く。全体図に詰め込まない。
- **処理の手順(入力 → 演算 → 出力)を箱で並べない。回路として描く**(`schematic: true`):

| 回路の要素 | 記号(`shape`) | 書くこと |
|---|---|---|
| セレクタ | `mux` 台形 | 入力に 0・1・2(`pins: {w: ["0", "1"], n: [sel]}`)。選択信号は斜めの辺から。名前は選択信号と反対側 |
| レジスタ | `reg` 縦長の箱 + 下にクロックの三角 | 名前とビット幅。三角の色 = クロック。端子は d(左)→ q(右) |
| 演算器 | `op` 丸の中に記号(`sym: "×"`・`"+"`・`"≫"`) | 名前と個数・ビット幅 |
| SRAM・ROM | `ram` 橙の箱 | 語数 × ビット幅、ポート数。端子名(waddr・wdata・raddr・rdata)を箱の中に |
| FIFO | `fifo` 仕切った箱 | 名前、どこから / どこへ |
| 制御(FSM・アドレス生成・デコーダ) | 形なし = 箱 | 名前と要点。出す信号を端子に |

- **線は端子につなぐ**(`from: areg.q`、`to: asram.wdata`)。**同じ出力端子から出る線は 1 本の配線**: 幹を共有し、分かれる所に **●**。
- **データ = 実線、制御 = 破線。** ラベルは**信号名とビット幅だけ**(バスの斜線つき。太さもビット幅)。帯域とクロック周波数は全体図と表に書く。
- **線をまっすぐつなぐ**: 記号は行の中央に置く(名前の帯を上下に同じだけ取る)。端子は行・列の中央に合わせる
  (3 行にまたがるセレクタの入力 0・1・2 は各行の中央)。隣どうしは同じ高さの端子で結ぶ。
- **データは左 → 右。制御(FSM・アドレス生成)は上の行。右から左へ戻る線(書き戻し・帰還)は下を回す。**
- 列の幅・行の高さは記号と文字から自動で決まる(マスは位置関係だけを表す)。空きマスがあってよい。
- **別の層にある回路**(真上のメモリダイの SRAM など)は薄い色の地の上に、その層の色の線で描く。層をまたぐ線に ⊠(`via: HB, far: line`)。
- 回路図ソフトの出力に合わせる必要はない。目的は、読む人が論文・ホワイトペーパーの回路アーキテクチャ図として読めること。

### R61 同じ線を何度も使う動作: 番号をまとめ、動作の表とコマ割りで示す
- メモリを読む → 演算する → 書き戻す → 読み直す → 演算器を切り替える、のような動作を 1 つの `scenes:` に書く。
- **番号**: 線を使うステップをまとめて書く(`1·4·7` = 1・4・7 番目で使う)。
- **動作の表**(図の下。ステップの `state:` から作る): 列 = ステップ、行 = セレクタ・メモリ・レジスタ、
  マス = その時の選択(`0: 積和`)・読み書き(`W 入力` / `R 重み`)・動き(`累算` / `保持`)。
  **前のステップから変わったマスは濃い色**(切り替えが目に入る)。
- **コマ割り**(`frames: true`): 同じ図を 1 ステップずつ並べ、そのステップで動く線とブロックだけを橙にする。
  配置はどのコマも元の図と同じ。コマの題の下に、そのステップの `state` を 〔 〕 で書く。
- ステップの文は「何を選び、どこから読み、どこへ書くか」を書く。くり返しは「2〜3 を窓の数だけくり返す」のように文で書く。

## model.yaml の書き方
```yaml
title: 推論アクセラレータ XA-1 アーキテクチャ全体図
view: top                 # 視点: top / bottom
grid: [12, 8]             # 列, 行
focus: [data, ctrl]       # 全体図に描く線の種類(ほかは別図 arch_focus_<種類>)
small_kinds: [clk, pwr, test]   # 名前だけの小さい箱にする種類
stack:                    # 下(基板側)から順
  - {id: L1, name: ロジックダイ, face: up, note: "5nm"}
  - {id: L2, name: メモリダイ, face: down, flip: y, at: [2, 0, 8, 7]}   # flip: 裏返す軸(y = 縦軸まわり → 左右反転)。at: 層の範囲
bonds:
  - {between: [L1, L2], type: HB, note: "6µm ピッチ"}
clocks:
  - {id: clk_core, freq: 2GHz, from: pll0}
blocks:
  - {id: dma, die: L1, at: [1, 3, 1, 2], name: DMA・入出力キュー, kind: ctrl, clock: clk_host,
     inside_dir: v, inside_flow: false, inside: ["fifo:入力 8MB", "fifo:出力 2MB", "mem:再送バッファ"]}   # fifo: = アイコン、mem: = 橙。| で改行
  - {id: "tile{i}", die: L1, at: [2, 1, 2, 2], array: [4, 2], pitch: [2, 3], name: "演算タイル {i}", kind: compute, clock: clk_core}
  - {id: pll0, die: L1, at: [0, 7, 1, 1], name: PLL0, kind: clk}          # 小さい箱(名前だけ)
links:
  - {id: h1, from: host_phy, to: host_ctl, dir: both, lanes: 16, rate: 64Gbps, proto: PIPE}
  - {id: g1, from: gpio, to: csr, dir: half, width: 1, rate: 1MHz, proto: I2C, kind: ctrl}
  - {id: "w{i}", from: "wmem{i}", to: "tile{i}", for: 8, via: HB, width: 2048, clock: clk_mem}      # 層をまたぐ(真上・真下)
  - {id: "bt{i}", from: mbist, to: "wmem{i}", for: 8, width: 64, clock: clk_mem, kind: test, mux: "通常/BIST"}   # 別図 arch_focus_test
scenes:
  - id: infer
    title: 推論 1 回
    steps:
      - {text: ホストが入力を送る, links: [h1, h2]}
crops:
  - {id: tile4, title: タイル 4 のまわり, blocks: [spine, tile4, red], scene: infer}
details:                  # ブロックの中の回路(別図)
  - id: tile
    of: ["tile*"]         # 全体図のどのブロックの中か(「▸中の回路: 別図 tile」の印が付く)
    schematic: true       # 回路図ふうに描く
    grid: [9, 4]
    stack_at: {L2: [0, 0, 4, 1], L1: [0, 0, 9, 4]}     # この図での各層の範囲
    blocks:
      - {id: asram, die: L1, at: [2, 1, 1, 3], name: 作業 SRAM, shape: ram, info: ["512b × 32768 語"], pins: {w: [wdata], n: [waddr, raddr], e: [rdata]}}
```

- `kind`: compute / mem / io / ctrl / clk / pwr / test / reg(塗りの色。小さい箱にするかの既定)。
- 線: `width` + `clock`(または `rate`)、直列は `lanes` + `rate`。`eff`(稼働率)、`proto`、`label`、
  `kind: data | ctrl | test | clk | pwr`、`dir: both | half`、`mux:`(セレクタの名前)、`from_side` / `to_side: n|s|e|w`(出入りする辺)。
- 層をまたぐ線: `via: HB`(真上・真下。⊠ を重なりの中に置く)、`far: true`(離れている。⊠ を両方に置き、相手の名前を書く)、`far: line`(線で結び、途中に ⊠)。
- ブロック: `label_at: tl | tr | bl | br`(文字の位置)、`inside_at: [0.3, 1]`(中身の箱の横の範囲)、`inside_y`、`inside_flow: false`(矢印なし)、`small: true | false`。
- 回路の図(`schematic: true`)のブロック: `shape: mux | reg | op | ram | fifo`(なし = 箱)、`out: e|w|n|s`(セレクタの出力の向き)、`sym`(演算器の記号)、
  `pins: {w: [...], e: [...], n: [...], s: [...]}`。既定の端子: reg は `d`(左)→ `q`(右)、fifo は `in` → `out`、op・mux の出力は `y`。
- 動作説明: `steps[].links`(使う線)、`steps[].state: {ブロック: その時の状態}`(動作の表)、`frames: true`(コマ割り)、`frame_cols`(1 行のコマ数)。

## 仮置きにしていること(決まったら直す)
- 裏返す軸の既定は縦軸まわり(左右が反転)。
- 帯域の単位は GB/s(バイト)。ビット/秒で見たい時は要相談。
- 上の層の色は 2 層目 = 紫、3 層目 = 緑、4 層目 = 赤紫。3 層以上は実例で未確認(文字の位置が右上・左下になる)。
- 小さい箱にする種類は clk・pwr・test。全体図に描く線は data・ctrl。
- 回路の図の記号は論文の図に寄せた独自のもの(IEEE の論理記号ではない)。ゲート 1 個ずつまで描く図は `gatediag.py`(ゲートレベル図)を使う。
- 回路の図の線のラベルは信号名とビット幅だけ(帯域・クロック周波数は書かない)。
