# RTL の接続データベース(rtldb.py)

RTL の接続を SQLite のデータベースにし、図(ブロック間の接続図・クロック/CDC の表)と検査の元にする。

```
python3 scripts/rtldb.py build -o design.db --top TOP -I incdir a.v b.sv ...   # RTL → DB(-f ファイル一覧 も可)
python3 scripts/rtldb.py analyze design.db -o out/ --png [--static '正規表現'] [--async-in '正規表現']
                                                    # クロック・CDC・RDC → cdc.md, cdc_map.svg, cdc_hier.svg
python3 scripts/rtldb.py path design.db --src 正規表現 --dst 正規表現           # 送り側から受け側までの経路(階層をまたぐ信号の並び)
python3 scripts/rtldb.py iface design.db --inst top.u_x -o iface.yaml          # → ifdiag.py render iface.yaml
python3 scripts/rtldb.py selftest                                              # 答えのわかる RTL で分類を確かめる
python3 scripts/cdcdiag.py hier design.db -o out/ --png [--focus 階層] [--rows 36] [--arcs 28] [--sev bad,review]   # CDC 階層図
python3 scripts/cdcdiag.py detail design.db --dst 正規表現 -o out/x.yaml        # CDC 詳細図 → gatediag.py render
```
図の決まりは `diagrams/cdc/GUIDE.md`(R54)。
必要: `pip install pyslang`(slang。SystemVerilog 2017 のエラボレータ)。

## 方式
1. **エラボレート**: slang でパラメータ・generate・マクロ・インスタンス配列を展開する。見つからないモジュールはブラックボックス。
2. **節点 = 信号**: 端子・ネット・変数を階層パス(`top.u_a.u_b.sig`)で一意にする。まとめすぎると別のクロックの信号が混ざるので、次の単位まで分ける。
   - 構造体はメンバごと(`clocks_o.clk_main` と `clocks_o.clk_io` は別の節点)。構造体どうしの代入・端子接続はメンバごとに 1 対 1。
   - 構造体の配列(packed / unpacked、256 要素まで)は要素ごと(`alert_rx[23].ping_p`)。定数の添字・範囲はその要素だけ、定数でない添字は同じ名前のメンバ全部。
   - ベクタは、定数の添字・範囲で読み書きされた所だけ「一部」の節点(`sync[0]`、`data[7:4]`)を作る。重なる範囲はつなぐ。
     `{a, b}` の代入はビットの範囲ごとに分ける(`sync <= {sync[0], d}` が 2 段の同期化に見える)。
     そのままの受け渡し(`assign y = x`、端子の接続)は、一部の範囲を元の信号までさかのぼって運ぶ。
   - メモリ(unpacked 配列)と、定数でない添字(for 文の `q[i]`)はまとめたまま。
   - 多対多の代入(定数でない添字の構造体配列など)は中継の節点(hub)を 1 つはさみ、辺の数を積にしない。
3. **辺 = 駆動**(`dst` ← `src`):

   | kind | 元の記述 | 付ける印 |
   |---|---|---|
   | comb | assign / always @* / ゲート / `wire x = 式` | role(data = 右辺、ctrl = if・case の条件・添字)、direct(論理を通らない) |
   | seq | クロックのエッジで叩く代入(dst は FF) | 同上。FF のクロック信号とエッジは `ff` 表 |
   | conn | インスタンスの端子接続 | direct |
   | arst | 非同期リセット(イベントにあり、先頭の if の条件に出る信号) | |
4. **クロックの源**: FF のクロック信号から駆動を逆にたどる。
   - トップの入力 = primary、ブラックボックスの出力 = blackbox(PLL など)、FF の出力 = generated(分周)
   - 合流点でクロックらしい源が 1 本(残りはイネーブル)= ゲート → 元のドメインのまま
   - クロックらしい源が 2 本以上 = mux(切替)→ 別のドメイン
   - generated は元のドメインと同じ「系」(同期)とし、CDC にしない
5. **CDC**: FF ごとに、入力の論理の円錐を FF・入力まで逆にたどり(メモ化)、系の違う FF があれば乗り換え。2 回に分けて分類する。
   1 回目で同期化の鎖(1 本を受けて同じドメインの次の FF へ直結)を全部見つけ、2 回目でそれを使って残りを分類する。

   | 分類 | 条件 | 重さ |
   |---|---|---|
   | sync | 1 本を受け、同じドメインの次の FF へ直結(2 段以上)。途中の反転・バッファは可。`if (x) q<=1; else q<=0;` の形も同じ | 同期化あり |
   | sync_gray | 同上で多ビット、名前に gray | 同期化あり |
   | sync_pulse | 同期化の鎖の 2 つの段を同じ論理で使う(エッジ検出・トグルの受け渡し) | 同期化あり |
   | fifo | 別クロックで書くメモリで、同じ階層(か 1 つ上)に 書き側 → 読み側 の同期化があり、書き込みの条件が 読み側 から同期化した信号で作られている | 同期化あり |
   | handshake | 受け側の条件で取り込むデータで、その条件が送り側ドメインから同期化した信号で作られている(FF 3 段まで戻って探す) | 同期化あり |
   | gated | 送り側の FF が、受け側に入る前に必ず「送り側ドメインから同期化した信号」と組み合わせ論理で合わさっている | 要確認(ゲートの種類とタイミング) |
   | sync_bus | 多ビットを FF で同期化 | 要確認(グレイかハンドシェイクか) |
   | data_enable | 受け側ドメインの条件で取り込むデータ(条件の同期化は見つからない) | 要確認 |
   | mem | 別クロックで書くメモリを読む(ポインタの同期化は見つからない) | 要確認 |
   | reconv | 同じインスタンスの送り側 FF を別々に 1 ビットずつ同期化し、受け側の 1 つの FF で合わせている | 要確認(ずれて届く) |
   | clk_as_data | クロック(源・切替の元)を FF のデータに使っている | 要確認 |
   | sync_logic | 2 本以上(または多ビット)を論理でまとめてから同期化 | 要対策(グリッチ) |
   | sync_tap | 1 段目の出力を次の FF 以外でも使用 | 要対策 |
   | no_sync | 上のどれでもない | 要対策 |
   | static | `--static` で準静的と宣言した送り側(動作中に変えない設定レジスタ) | 対象外 |

   `--async-in '正規表現'` で指定したトップの入力端子は、それぞれ別のドメイン(非同期入力)として扱う。
   `cdc.via` に、条件・ポインタを同期化している FF(1 段目)を残す(詳細図で使う)。
6. **RDC(非同期リセット)**: FF のリセット端子を逆にたどり、源ごと・受け側ドメインごとに数える。

   | 分類 | 条件 |
   |---|---|
   | rst_sync | リセットを出している FF と、その前段(リセット同期化回路) |
   | rst_ok | 同じドメインの FF 1 本が出すリセット |
   | rst_input | 入力端子・ブラックボックスのリセットを直接使用(解除が非同期・要確認) |
   | rst_logic | 同じドメインの FF 2 本以上の論理で作るリセット(グリッチ・要確認) |
   | rst_cross | 別ドメインの FF が出すリセット(要対策) |

## 表
`instance`(階層)/ `signal`(節点)/ `edge`(駆動)/ `ff`(クロック・ドメイン)/ `clock`(ドメイン・種類・系)/ `cdc`(乗り換え)/
ビュー `conn`(ブロック間の端子接続)。SQL でそのまま引ける:
```sql
SELECT src_inst, src_port, dst_inst, dst_port, width FROM conn WHERE dst_inst='top.u_npu';
SELECT d.path, c.class FROM cdc c JOIN signal d ON d.id=c.dst WHERE c.class='no_sync';
```

|---|---|---|

| `examples/rtl/cdc_deep.sv`(深い階層) | 階層 9 段・構造体・構造体の配列・generate・再帰インスタンス | 送り側 8 段下 → 受け側 9 段下 の同期化・ハンドシェイク・同期化なし・非同期 FIFO を全て検出。全部同じクロックのレーン・同じドメインの要素には出ない |
| **OpenTitan top_earlgrey**(SystemVerilog 51.5 万行・823 ファイル) | 38,654 インスタンス / 節点 68.6 万 / 辺 280 万 / FF 21,797(信号単位)/ 階層 11 段 | 抽出 44 秒 + 解析 37 秒、DB 394MB。ドメイン: io 12,207・sys 7,717・aon 1,186・usb 545・JTAG 2 本など。受け側 FF 単位で 非同期 FIFO 8,606・同期化あり 597・ハンドシェイク 127・ゲートの形 430・再収束 105・多ビット同期 49・同期化の前に論理 43・同期化なし 137。乗り換えの両端は最大 8 段下、上がり + 下がりは最大 12 段 |
| OpenCores ethmac(Verilog, 約 1.2 万行) | 66 インスタンス / FF 427 | ドメイン 3(wb・mtx・mrx)。設定レジスタを準静的と宣言後、同期化なし 52・同期化の前に論理 4・1 段目の使用 2・エッジ検出 9・ハンドシェイク 9 |
| verilog-ethernet Arty の fpga_core(約 4.6 万行を読み込み) | 41 インスタンス / FF 625 | ドメイン 3。非同期 FIFO・グレイポインタ・リセット/状態の同期化を検出(初版で確認) |
| Ibex(SystemVerilog) | 37 インスタンス / FF 115 | ドメイン 1(クロックゲートは同じドメイン)、乗り換え 0(初版で確認) |

OpenTitan でソースと突き合わせた例(`rtldb.py path` で経路を出して確認):
- `u_alert_handler.gen_alerts[23]…ping` → `u_usbdev.gen_alert_tx[0]…i_sync_p.u_sync_1`: 構造体の配列 `alert_rx[23]` を通る 20 節点の経路を 1 本に特定(ほかの 67 本と混ざらない)。途中の `prim_buf`(反転 2 つ)は論理に数えず、同期化あり。
- `prim_reg_cdc` の `txn_bits_q & {N{dst_req}}`: 同期化したパルスでゲートして渡す形 → gated(要確認)。
- `u_otp_ctrl` の OTP の値 → `u_keymgr_dpe` / `u_kmac`: 同期化なしで別ドメインへ。設計上は準静的な値で、`--static` の宣言が要る所。
- `prim_mubi4_sync`: 4 ビットの符号を 2 段で同期化 → sync_bus(要確認。符号の安定は別に見る)。
- `u_pinmux` の wkup 検出: レジスタで選ぶ MUX の後ろで同期化 → sync_logic。

改良の経過(同じ OpenTitan で): 初版は全クロックが構造体 1 つに混ざって 1 ドメイン → メンバ単位に分けて 12 ドメイン。
「同期化なし」は 6,813 → 非同期 FIFO の認識で 495 → ビット範囲・構造体配列の追跡とゲートの形の認識で 137。

FF の数は信号単位(バスは 1 つ、一部だけ代入した所はその範囲ごと)。

## 限界
- 分類は構造だけで決める。グレイコードは名前で判断。ハンドシェイク・ゲートの形は「同期化した信号で条件が作られている」所までで、
  送り側がその間データを変えないこと・ゲートが AND か、は見ない(人が確認する)。
- 定数でない添字(for 文の `q[i]`)・出力端子につないだ連接(`.q({a, b})`)・unpacked 配列はビットや要素を分けずにまとめる。
  ここを通ると、別々の信号が 1 つに見えて「同期化の前に論理」「同期化なし」が多めに出る。
- 再収束は、同じインスタンスの送り側どうしで、組み合わせだけで合流するものに限る(FF をはさんだ先の合流は見ない)。
- 分周クロックは元と同期とみなす。SDC の `set_clock_groups` は読まない(系の同期・非同期は構造から決める)。
- ラッチは組み合わせとして扱う。関数の中はたどらず、引数を依存にする。
- 規模: 50 万行で DB 約 400MB・メモリ数 GB。それ以上は IP ごとに分けて作る。
