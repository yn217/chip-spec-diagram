# ゲートレベル図

仕様書で回路の動きを説明する小さな回路図(リセット同期化・クロック切替・クロックゲート・CDC の同期化・エッジ検出など)。
標準の記号(AND/OR/NAND/NOR/XOR/XNOR/NOT/BUF・MUX・FF・ラッチ・ICG)で、ネットリスト形式の YAML から自動で配置・配線する。

## 入力
- YAML(書式は `scripts/gatediag.py` の先頭): `ports`(dir: in/out、`async: true` = 非同期の入力、`clock: true`)・
  `cells`(type と各端子の網名)・`nets`(バス幅)・`groups`(説明の囲み)・`note`
- RTL がゲートのインスタンスで書かれている(合成後ネットリストや手書きの構造記述)なら
  `python3 scripts/gatediag.py netlist top.v -m モジュール -o gate.yaml` で YAML を作る。対応表にないセルは info に出るので type を足す。
  `always` などの動作記述は読まない(合成してから、または手で YAML を書く)。

## 手順
1. 何を説明する回路か、入出力とクロック・リセットを確認する。未決の所は仮置きして決定事項ログへ。
2. `python3 scripts/gatediag.py render gate.yaml -o out/ --png`
3. lint が OK になるまで直す。わかって受けている CDC は FF に `cdc_ok: "理由"`、わかって論理で作るクロックはゲートに `clock_ok: true`。
4. PNG を見て、線が記号や文字に重なっていないか確認する。

## 描き方の決まり(R52)
- 左から右へ信号の流れ順に列を作る。2 列以上離れる接続は中継点を入れてまっすぐ通す。列の間の通路に縦の幹線、分岐点に黒丸。
- 戻りの接続(FF の出力を前の段へ返す)は図の上を回す。
- 網の色: クロックは元の端子ごとに色(ゲートを通った後も同じ色、複数のクロックが合流したら灰色)、リセットは茶色、データは黒。バスは太線と斜線+幅。
- FF のクロック端子は三角(立ち下がりは丸付き)。負論理の端子は丸。定数は端子の前に 0/1。
- セルの上に名前、下に注記(紫)。文字は白い縁取りで線と重なっても読めるようにする。

## チェック(lint)
| タグ | 内容 |
|---|---|
| [未接続] | 入力がつながっていない / 駆動元のない網 |
| [複数駆動] | 1 つの網を 2 つ以上の出力が駆動 |
| [ループ] | FF・ラッチを通らない組み合わせのループ |
| [クロック] | FF/ラッチのクロックを論理ゲートで作っている(ICG を使う) |
| [CDC] | 別のクロックの FF(や `async: true` の端子)から 1 段で受けている / 論理を通してから同期化している |
| [未定義] | 使えない type |
