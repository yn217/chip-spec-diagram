# データフロー検討図(フロアプラン風)

ダイのどの辺のどこからデータが入り、PHY → コントローラ → バス → どの SRAM・演算器に届くかを、
フロアプランに近い配置の上に太い矢印で描く。経路ごとに、通過する要素・チップ内の配線距離(マンハッタン距離の目安)・
帯域と上限(ボトルネック)を表にする。実寸の配置検討は `floorplan.py`、こちらは流れの検討用。

## 入力
バス構成図と同じ `diagram.yaml` に `dataflow_floorplan:` を足す(書式は `scripts/dataflowfp.py` の先頭)。
- 何も書かなくても、バス構成図の配置をダイに写し、端子(`pads`)の辺に PHY を自動で置く。
- `die`(mm)・`blocks`(位置の上書き・追加、mm・左下原点)・`phy`(名前・長さ・位置)・`buses`(帯の高さ)
- `flows`: `from`/`to` だけ書けば、結線とバスから経路を探す。`path` で直接書いてもよい。`bw` を書くと上限と比べる。
- `scenario: true` でストーリーボードの経路も描く。`max_mm` で長すぎる経路を知らせる。

## 手順
1. 入口(どの辺の、どの端子から)と行き先(どの SRAM・演算器)を確認する。未決は仮置きして決定事項ログへ。
2. `python3 scripts/dataflowfp.py diagram.yaml -o out/ --png` → `dataflow_fp.svg` と `dataflow.md`
3. lint を直す。配置を変える案は `blocks` の `at` で上書きして比べる(案A・案B)。

## 描き方の決まり(R53)
- ダイの外周(破線)に PHY を端子の辺に沿わせて置き、辺の上に端子(四角)、外にチップ外のブロック(破線)。
- バスは、つながるブロックの間の空いた高さに帯で通し、ブロックから帯へ細い線。
- 流れは太い矢印(太さ = 帯域)、始点に番号、重なる区間は少しずらす。ブロック・PHY・端子の名前は矢印の上に白縁で。
- 表: 番号・名前・経路(端子 → PHY → コントローラ → バス → 行き先)・距離・帯域・上限。

## チェック(lint)
| タグ | 内容 |
|---|---|
| [到達] | from から to への経路が見つからない |
| [帯域] | 流す帯域(bw)が、通る端子・バスの帯域を超える |
| [距離] | チップ内の配線距離が max_mm を超える |
| [辺] | PHY がダイの辺に接していない |
